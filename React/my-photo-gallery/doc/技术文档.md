### **1\. 前端 (Frontend) \- 浏览器中的“表现层”**

前端是项目的第一印象，负责所有用户能看到和交互的界面。

* **核心框架 (Core Framework):**

  * **React (v18+)** 2：你项目的核心，一个用于构建用户界面的 JavaScript 库。我们使用它来创建可复用的UI组件（如 Header.jsx, HomePage.jsx）。
* **构建工具 (Build Tool):**

  * **Vite** 3：一个极速的现代前端构建工具。我们用它来创建和运行你的 React 项目，它提供了闪电般的“热更新”（HMR）开发体验。
* **页面路由 (Routing):**

  * **React Router Dom**：我们用它来管理你的单页面应用（SPA）路由，实现了从 / 到 /login 和 /admin 的页面跳转。
* **UI 样式 (Styling):**

  * **Tailwind CSS**：一个“原子化”的 CSS 框架。我们用它来快速构建美观的界面（如登录页、管理后台布局），而无需编写大量的自定义 CSS。
* **状态管理 (State Management):**

  * **Redux Toolkit** 4：根据开题报告，这是你计划用来管理全局状态（例如用户登录信息、全局作品数据）的工具，它能让复杂的状态管理变得简单可预测。
* **3D 渲染 (3D Rendering):**

  * **Three.js** 5：用于在网页上创建和显示 3D 图形。
  * **React Three Fiber & Drei**：我们用来将 Three.js 声明式地集成到 React 中的库，极大地简化了 3D 展廊（Gallery3DPage.jsx）的开发。
  * 通过Three.js加载GLB格式的全景模型，结合OrbitControls库实现视角控制，并采用渐进式加载技术优化用户初始加载时间。
  * 
* **API 通信 (API Communication):**

  * **Fetch API (封装在 network.js 中)**：用于和你的后端服务器进行数据交互（如获取作品、提交登录请求）。

### **2\. 后端 (Backend) \- 服务器上的“业务逻辑层”**

后端是你项目的大脑，负责处理数据、验证用户身份和执行所有核心业务逻辑。

* **运行环境 (Runtime):**

  * **Node.js** 6：一个基于 Chrome V8 引擎的 JavaScript 运行环境，让你可以使用 JavaScript 来编写服务器端代码。
* **核心框架 (Core Framework):**

  * **Koa.js** 7：根据开题报告，你将使用 Koa.js。它是一个轻量级、灵活的 Node.js 框架，非常适合用来快速构建高效的 API 服务。
* **API 风格 (API Style):**

  * **RESTful API** 8：你将设计和实现一套 RESTful 风格的 API 接口（如 GET /api/artworks 或 POST /api/auth/login），供前端调用。
* **图像处理 (Image Processing):**

  * **Sharp.js** 10：根据你的开题报告，当用户上传图片时，后端将使用 Sharp.js 库在服务器上自动对图片进行压缩、裁剪和格式转换（例如转为高性能的 WebP 格式）。

### **4\. 项目技术模块分解**

#### **1\. 用户与认证模块 (User & Auth Module)**

* **功能描述**：实现用户的注册、登录、身份验证和个人资料管理。
* **前端技术**：
  * **React 组件**：LoginPage.jsx 和 RegisterPage.jsx，用于构建登录和注册的表单。
  * **React Router**：react-router-dom 用于在 /login, /register 和应用主页之间跳转。
  * **API 通信**：api/network.js 中的 loginUser 和 registerUser 函数，使用 fetch 向后端发送登录/注册请求。
  * **状态管理**：**Redux Toolkit** (根据你的报告 2)，用于在全局存储用户的登录状态（如 token 和用户信息），并在 Header.jsx 中动态显示“登录/注册”或“我的主页”。
* **后端技术**：
  * **Koa.js**：创建 /api/auth/login 和 /api/auth/register 路由，用于接收前端请求。
  * **JWT (JSON Web Tokens)**：(根据你的报告 3) 用于身份认证。用户登录成功后，后端生成一个 token 发给前端。前端在后续所有需要权限的请求中携带此 token。
  * **(密码加密)**：使用 bcrypt 库对用户密码进行哈希加密，确保安全。
* **数据库技术**：
  * **PostgreSQL**：在 users 表中存储用户信息，包括用户名和**加密后**的密码 4。

#### **2\. 摄影作品管理模块 (Artwork Management)**

* **功能描述**：用户上传、编辑、删除和展示摄影作品。
* **前端技术**：
  * **React 组件**：UploadPage.jsx 提供作品上传表单。HomePage.jsx 使用 CSS Grid 或 Masonry 布局来瀑布流展示作品
  * **性能优化**：react-lazyload 实现图片懒加载，加快首页打开速度。
  * **大文件上传**： 前端将实现**分块上传**和**断点续传**，提高大体积图片上传的稳定性和效率。
* **后端技术**：
  * **Koa.js**：创建 /api/artworks 路由 (POST, PUT, DELETE) 来处理作品的增删改。
  * **图像处理**：**Sharp.js** 库 ，在后端接收到图片后，自动进行压缩并统一转换为高性能的 **WebP 格式**。
* **数据库技术**：
  * **PostgreSQL**：在 artworks 表中存储作品的**元数据**，如作品ID、标题、描述、作者ID以及存储在 OSS 上的图片URL

#### **3\. 3D 沉浸式展廊 (3D Gallery Module)**

* **功能描述**：为特定作品（如全景摄影）提供沉浸式的 3D 浏览体验
* **前端技术**：
  * **React 组件**：Gallery3DPage.jsx 是该功能的主页面。
  * **3D 渲染**：**React Three Fiber** (@react-three/fiber) 作为核心渲染器，它提供了 React 组件式的 Three.js 体验。
  * **辅助工具**：**Drei** (@react-three/drei) 提供了大量现成的3D辅助组件，例如我们用到的 \<Box\> (几何体), useTexture (纹理加载) 和 \<PointerLockControls\> (第一人称漫游控制器)。
  * **核心库**：**Three.js** (作为 R3F 的底层库) ，提供 THREE.BackSide 等核心常量。
* **后端技术**：
  * 后端主要负责提供作品的图片 URL (来自 OSS)。3D 渲染和交互逻辑**完全在前端浏览器中**完成。
* **数据库技术**：
  * **PostgreSQL**：artworks 表中可能需要一个字段，用于标记哪些作品拥有 3D 模型或全景图资源。

#### **4\. 摄影技巧社区 (Community Module)**

* **功能描述**：用户发布和浏览摄影教程、后期处理方法等内容，并支持标签分类和检索
* **前端技术**：
  * **React 组件**：CommunityPage.jsx，我们已经构建了该页面的框架，包括搜索框、标签筛选按钮和文章卡片列表。
  * **React State**：使用 useState 来管理搜索词和当前选中的标签，动态筛选列表内容。
  * **API 通信**：api/network.js 中将添加 getCommunityPosts() 等函数，用于从后端获取或筛选文章数据。
* **后端技术**：
  * **Koa.js**：创建 /api/community/posts 路由，支持通过查询参数（如 ?tag=人像摄影 或 ?search=后期）来进行数据筛选。
* **数据库技术**：
  * **PostgreSQL**：创建 community\_posts 表来存储文章内容。可能还需要一个 tags 表和一个 post\_tags 关联表来实现多对多的标签功能

#### **5\. 互动交流模块 (Interaction Module)**

* **功能描述**：用户对作品进行评论、点赞、收藏，以及查看作者的拍摄参数
* **前端技术**：
  * **React 组件**：在作品详情页中，开发 \<CommentList\>, \<LikeButton\> 等组件。
  * **数据展示**：解析后端传来的 JSON 格式的拍摄参数（光圈、快门、ISO 等）并展示在页面上。
* **后端技术**：
  * **Koa.js**：创建嵌套路由，如 /api/artworks/:id/comment (POST) 和 /api/artworks/:id/like (POST)，用于处理特定作品的互动请求。
* **数据库技术**：
  * **PostgreSQL**：创建 comments 表（关联 user\_id 和 artwork\_id）和 likes 表（或 favorites 表）

#### **6\. 管理员后台 (Admin Panel)**

* **功能描述**：实现用户管理、作品审核、评论管理、内容推荐和数据统计看板
* **前端技术**：
  * **React Router**：使用**嵌套路由** (\<Route path="/admin" element={\<AdminLayout /\>}\> ... \</Route\>) 来实现后台的整体布局和页面切换。
  * **React 组件**：AdminLayout.jsx (左侧菜单布局), Dashboard.jsx, UserManagement.jsx 等（右侧功能页面）。
  * **UI 库**：(推荐) 可能会引入如 Ant Design 或 MUI 这样的组件库来快速搭建后台所需的表格、图表和表单。
* **后端技术**：
  * **Koa.js**：创建一套独立的 /api/admin/... 路由。
  * **权限中间件**：在所有 admin 路由上应用一个中间件，该中间件会校验用户的 **JWT**，确保只有“管理员”角色的用户才能访问。
* **数据库技术**：
  * **PostgreSQL**：后端 admin 接口将对所有表（users, artworks, comments）执行更高权限的 CRUD（增删改查）操作，例如修改 artworks 表中的 is\_approved 状态字段。
