### 1. 业务功能

从 `DEVELOPER_GUIDE.md` 和 `backend/routes/posts.js` 文件的内容来看，这个项目是一个移动端应用程序，其核心业务功能是**内容发布和浏览**。

主要功能点包括：

* **用户认证：** 提供用户注册、登录、找回密码等功能。
* **内容创建（发帖）：** 允许用户创建新的“项目”或“帖子” (Item/Post)。这可能包括上传图片（提到了 `react-native-image-picker` 和 Firebase Storage）。
* **内容浏览：** 用户可以查看和浏览“项目”或“帖子”的列表。
* **数据管理：** 后端 API 提供了对“帖子”的完整 CRUD（创建、读取、更新、删除）操作。

`DEVELOPER_GUIDE.md` 还提到了一个“模拟服务” (mock services) 的概念，允许前端开发者在没有真实后端的情况下，使用模拟数据进行 UI 开发和测试。

### 2. 架构逻辑

该项目采用**前后端分离**的架构。

1.  **前端 (Frontend)：**
    * **技术栈：** 一个使用 **React Native** 和 **Expo** 框架构建的移动端 App。
    * **目录：** 位于 `frontend` 文件夹。
    * **职责：** 负责所有用户界面 (UI) 的展示，如登录/注册页面、首页、创建帖子页面等。它通过 HTTP 请求与后端 API 进行通信。
    * **依赖：** 从 `frontend/package.json` 可以看到它依赖 `expo`、`react-native`、`@react-navigation/native`（用于导航）和 `firebase`（用于客户端 Firebase 服务）。

2.  **后端 (Backend)：**
    * **技术栈：** 一个使用 **Node.js** 和 **Express** 框架搭建的 API 服务器。
    * **目录：** 位于 `backend` 文件夹。
    * **职责：** 作为中间层 API，处理来自前端 App 的请求。它使用 **Firebase Admin SDK** 来与 Firebase 的各项服务进行交互（如读写数据库）。
    * **依赖：** 从 `backend/package.json` 可以看到它依赖 `express`、`firebase-admin`（用于连接 Firebase）和 `cors`（用于跨域）。

3.  **数据库和服务 (Database & Services)：**
    * **技术栈：** 项目重度依赖 **Google Firebase** 套件。
    * **Firestore：** 作为主数据库，用于存储应用数据，例如用户信息和“帖子”内容。
    * **Firebase Authentication：** 用于处理用户认证（登录、注册）。
    * **Firebase Storage：** 用于存储用户上传的文件，例如帖子的图片。

**数据流逻辑：**
用户在 **React Native (Expo) 前端** App 上操作 -> 前端 App 发送 API 请求到 **Node.js (Express) 后端**（例如 `http://<your-local-ip-address>:4000`） -> 后端服务器使用 **Firebase Admin SDK** 对 **Firebase (Firestore/Auth)** 进行数据读写 -> 后端将结果返回给前端 App。

### 3. 运行步骤

根据 `README.md` 文件，完整的本地开发环境启动步骤如下：

**前提条件：**
* 安装 [Node.js](https://nodejs.org/) (v20.18.1 或更高版本)。
* 安装 [npm](https://www.npmjs.com/) (通常随 Node.js 一起安装)。
* 安装 [Git](https://git-scm.com/)。
* (针对移动端模拟器)：安装 Xcode (macOS) 或 Android Studio (macOS/Windows)。

**步骤 1：克隆并进入项目**
1.  `git clone <your-repository-url>`
2.  `cd <repository-folder>`

**步骤 2：配置后端**
1.  进入后端目录：`cd backend`。
2.  安装依赖：`npm install`。
3.  **获取 Firebase 管理员凭证**：
    * 前往您的 Firebase 项目设置 -> 服务账号。
    * 生成一个新的私钥，这将下载一个 JSON 文件。
    * 将该文件重命名为 `serviceAccountKey.json` 并将其放入 `backend` 目录中。

**步骤 3：配置前端**
1.  进入前端目录：`cd ../frontend`。
2.  安装依赖：`npm install`。
3.  **创建环境变量文件**：
    * 在 `frontend` 目录中创建一个名为 `.env` 的文件。
    * 复制 `README.md` 中提供的环境变量模板内容到 `.env` 文件。
4.  **填充环境变量**：
    * **Firebase Keys：** 前往 Firebase 项目设置 -> 常规 -> “您的应用”，找到您的“Web 应用”。
    * 将 `apiKey`, `authDomain`, `projectId` 等值填入 `.env` 文件中对应的 `EXPO_PUBLIC_...` 变量。
    * **API URL：** 找到您电脑的局域网 IP 地址（macOS/Linux: `ifconfig`；Windows: `ipconfig`）。
    * 将 `EXPO_PUBLIC_API_URL` 的值设置为 `http://<your-local-ip-address>:4000`（请替换 `<your-local-ip-address>` 为您的真实 IP）。

**步骤 4：运行应用（双终端）**
你需要同时运行后端和前端。

1.  **启动后端服务器：**
    * 打开一个终端，进入 `backend` 目录。
    * 运行：`node index.js`。
    * 您应该会看到服务器在 4000 端口运行的消息。

2.  **启动前端开发服务器：**
    * 打开**第二个**终端，进入 `frontend` 目录。
    * 运行：`npx expo start`。
    * 这会打开 Expo 开发者工具。

**步骤 5：在模拟器上运行（首次设置）**
该项目使用**自定义开发构建**，不能直接在 Expo Go 中运行。

1.  **(仅首次) 构建开发应用：**
    * 确保您的 iOS 模拟器或 Android 模拟器已经启动。
    * 在**第二个**终端（`frontend` 目录）中，运行：
        * iOS: `npx expo run:ios`
        * Android: `npx expo run:android`
    

2.  **(日常) 启动应用：**
    * 确保**终端 1** 中的后端（`node index.js`）正在运行。
    * 确保**终端 2** 中的前端（`npx expo start`）正在运行。
    * 在运行 `npx expo start` 的**终端 2** 中，按 `i` 键（在 iOS 模拟器中打开）或 `a` 键（在 Android 模拟器中打开）。
    * App 将在模拟器上启动并连接到您的本地开发服务器。
